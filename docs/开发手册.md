## 三、核心设计模式与约定

### 3.1 统一返回体

所有Controller返回 `Result<T>`：

```java
// 成功返回
return Result.success(data);

// 失败返回
throw new BusinessException(ResultCodeEnum.PARAM_ERROR);
```

### 3.2 全局异常处理

`GlobalExceptionHandler` 统一拦截：
- `BusinessException` → 业务异常码 + 用户友好提示
- `MethodArgumentNotValidException` → 参数校验失败（400）
- `Exception` → 兜底500

### 3.3 实体基类

```java
// 业务实体（有逻辑删除 + 自动填充时间）
public abstract class BaseEntity {
    private Long id;
    @TableLogic
    private Integer deleted;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}

// 关联表/只追加表（无deleted/updatedAt）
// UserRole, RolePermission, ChatRecord 独立定义
```

### 3.4 文档状态机

基于枚举的轻量级实现，在 `DocumentStatus` 枚举中定义状态转移规则：

```java
public enum DocumentStatus {
    UPLOADED, PARSING, CLEANING, PENDING_REVIEW,
    APPROVED, REJECTED, CHUNKING, EMBEDDING, COMPLETED,
    PARSING_FAILED, CLEANING_FAILED, CHUNKING_FAILED, EMBEDDING_FAILED;

    // 每个状态的可达下一状态集合
    static {
        UPLOADED.nextStates = Set.of(PARSING);
        PARSING.nextStates = Set.of(CLEANING, PARSING_FAILED);
        // ...
    }

    public boolean canTransitTo(DocumentStatus target) {
        return nextStates.contains(target);
    }
}
```

状态转换在 `DocumentStateMachine` 中执行，使用乐观锁防止并发冲突。

### 3.5 分布式锁

两种使用方式：

```java
// 注解方式
@DistributedLock(key = "review:auto:#{#docId}", waitTime = 3, leaseTime = 10)
public void someMethod(Long docId) { }

// 编程方式
redisLockUtil.executeWithLock("myKey", () -> {
    // 业务逻辑
    return result;
});
```

### 3.6 限流

注解驱动，基于Redis滑动窗口 + Lua脚本：

```java
@RateLimit(key = "qa", permitsPerSecond = 10, message = "请求过于频繁")
@PostMapping("/chat")
public Result<AnswerVO> chat(...) { }
```

### 3.7 认证流程

```
用户登录 → 返回 access_token(2h) + refresh_token(7d)
       ↓
每次请求 → Authorization: Bearer <access_token>
       ↓
JwtAuthInterceptor → 解析JWT → ThreadLocal存储userId
       ↓
JwtAuthenticationFilter → 查询权限 → SecurityContext → @PreAuthorize生效
```

### 3.8 文件上传流程

```
Controller接收MultipartFile
  → FileServiceImpl.upload()
    → 流式计算MD5
    → 检查MD5去重（唯一索引）
    → MinIO putObject
    → 保存Document记录（status=UPLOADED）
    → Kafka发送处理消息 → Python消费者处理
    → 异步状态流转（PARSING → CLEANING → ... → COMPLETED）
```

## 四、如何添加新功能

### 4.1 添加新表

1. 在 `domain/entity/` 下创建Entity类
2. 在 `domain/mapper/` 下创建Mapper接口
3. 如需复杂查询，在 `resources/mapper/` 下创建XML映射文件
4. 更新 `sql/V1__init_schema.sql`（迁移脚本）

### 4.2 添加新接口

1. 在 `service/` 对应模块创建Service接口和实现类
2. 需要DTO/VO时在同级 `dto/` 下创建
3. 在 `controller/api/` 创建Controller
4. 需要权限控制时添加 `@PreAuthorize("hasAuthority('XXX')")`

### 4.3 添加新权限

1. 在 `sql/V2__init_data.sql` 中插入新权限记录
2. 在Controller方法上添加 `@PreAuthorize` 注解
3. 无需修改Java代码（权限由数据库驱动）

### 4.4 添加新系统配置项

1. 在 `sql/V2__init_data.sql` 中插入配置记录
2. 通过 `SystemConfigService` 读取：`getStringConfig("myKey", "defaultValue")`
3. 无需重启，配置变更自动刷新缓存

### 4.5 添加新的文档状态

1. 在 `DocumentStatus` 枚举中添加新状态值
2. 在静态初始化块中定义状态转移规则
3. Python端同步更新对应的状态处理逻辑

## 五、编码规范

### 5.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 包名 | 全小写 | `com.rag.service.file` |
| 类名 | 大驼峰 | `FileServiceImpl` |
| 方法名 | 小驼峰 | `uploadFile()` |
| 常量 | 全大写+下划线 | `QA_CACHE_PREFIX` |
| 数据库表 | 蛇形命名 | `knowledge_bases` |
| 数据库字段 | 蛇形命名 | `upload_user_id` |
| REST路径 | 短横线分隔 | `/api/knowledge-bases` |

### 5.2 Lombok使用

```java
// Service/Controller
@RequiredArgsConstructor  // final字段构造注入
@Slf4j                    // log对象

// Entity/DTO
@Data                     // getter/setter/toString/equals/hashCode
@TableName("users")       // MyBatis-Plus表名映射
```

### 5.3 参数校验

DTO中使用Jakarta Validation：

```java
@NotBlank(message = "用户名不能为空")
@Size(min = 3, max = 64, message = "用户名3-64位")
private String username;
```

Controller中使用 `@Valid` 触发校验：

```java
public Result<?> create(@Valid @RequestBody SaveDTO dto) { }
```

### 5.4 日志规范

```java
log.info("业务关键节点: userId={}, docId={}", userId, docId);
log.warn("异常但可恢复: {}", e.getMessage());
log.error("需要关注的错误", e);
```

- 不要使用字符串拼接：`"user:" + id`
- 不要打印敏感信息（密码、token全文）
- 不要使用 `e.printStackTrace()`

## 六、本地开发调试

### 6.1 启动步骤

1. 确保Docker基础设施已启动（见部署文档）
2. 初始化数据库：执行 `sql/` 下的SQL脚本
3. 编译proto：`mvn generate-sources`
4. IDEA中运行 `RagApplication.java`，profile选择 `dev`
5. 访问 Swagger：`http://localhost:8080/swagger-ui.html`

### 6.2 热更新

Spring Boot DevTools已集成在pom.xml中（dev profile自动启用），修改代码后自动重启。

### 6.3 调试技巧

```yaml
# application-dev.yml 中已配置
logging:
  level:
    com.rag: DEBUG                    # 项目代码DEBUG级别
    com.rag.domain.mapper: DEBUG      # SQL日志
```

- SQL执行日志：控制台输出参数和耗时
- 慢SQL告警：>1000ms会标记 `[SLOW SQL]`
- gRPC调用日志：DEBUG级别查看请求/响应内容
