# RAG知识库系统 — 部署文档

## 一、环境要求

| 组件 | 版本 | 用途 |
|------|------|------|
| Docker | 24+ | 容器运行时 |
| Docker Compose | 2.x | 多容器编排 |
| Java | 17 | 编译（仅本地构建） |
| Maven | 3.9+ | 构建工具（仅本地构建） |
| Python | 3.11+ | AI 服务（仅本地开发） |

全部中间件已容器化，无需本地安装 MySQL/Redis/Kafka/MinIO/Milvus。

## 二、容器化部署（推荐）

### 2.1 前置准备

创建 `.env` 文件（放在 `RAG-BACKEND/` 根目录，gitignore 已排除）：

```bash
# LLM 配置
LLM_API_KEY=sk-your-api-key
LLM_BASE_URL=https://api.deepseek.com
LLM_CHAT_MODEL=deepseek-chat

# MinIO 对象存储
MINIO_ROOT_USER=minioadmin
MINIO_ROOT_PASSWORD=minioadmin123
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin

# MySQL
MYSQL_ROOT_PASSWORD=root123
MYSQL_DATABASE=rag_db

# Redis
REDIS_PASSWORD=redis123

# JWT
JWT_SECRET=your-256-bit-secret-key-change-in-production
```

### 2.2 一键启动

```bash
cd RAG-BACKEND
docker-compose up -d --build
```

此命令将依次启动 8 个容器：

| 容器 | 镜像 | 端口 | 说明 |
|------|------|------|------|
| rag-mysql | mysql:8.0 | 3307→3306 | 业务数据库，自动执行 `sql/` 目录脚本 |
| rag-redis | redis:7-alpine | 6379 | 缓存 / 分布式锁 / 限流 |
| rag-kafka | apache/kafka:4.2.0 | 9092 | KRaft 模式（无需 Zookeeper） |
| rag-minio | minio/minio:latest | 9000, 9001 | 对象存储 + Web 控制台 |
| rag-minio-init | minio/mc:latest | — | 自动创建 `rag-documents` bucket |
| rag-etcd | quay.io/coreos/etcd:v3.6.11 | 2379 | Milvus 元数据存储 |
| rag-milvus | milvusdb/milvus:v2.6.16 | 19530, 9091 | 向量数据库 |
| rag-python | rag-python:latest | 50051, 50052 | Python AI 服务（gRPC + Kafka Consumer） |
| rag-server | rag-server:latest | 8080 | Java 业务控制中心 |

### 2.3 验证部署

```bash
# 所有容器应为 healthy
docker ps --format "table {{.Names}}\t{{.Status}}"

# Java 服务健康检查
curl http://localhost:8080/actuator/health
# → {"status":"UP"}

# 测试登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
# → {"code":0,"message":"success","data":{...}}
```

### 2.4 网络拓扑

所有容器加入 `rag-network`（bridge 模式），通过容器名互相通信：

```
rag-server (Java :8080)
    ├── MySQL    → mysql:3306
    ├── Redis    → redis:6379
    ├── Kafka    → kafka:9092
    ├── MinIO    → minio:9000
    ├── Retrieval gRPC → rag-python:50051
    └── Generation gRPC → rag-python:50052

rag-python (Python :50051/:50052)
    ├── Kafka    → kafka:9092
    ├── MinIO    → minio:9000
    ├── Milvus   → milvus:19530
    └── Redis    → redis:6379

rag-milvus
    ├── etcd     → etcd:2379
    └── MinIO    → minio:9000
```

## 三、应用构建

### 3.1 Java 服务（rag-server）

**Docker 构建**（Dockerfile 位于 `docker/Dockerfile`）：

```bash
docker build -t rag-server:latest -f docker/Dockerfile .
```

**Dockerfile 关键要点**：

- **构建阶段**：`maven:3.9-eclipse-temurin-17-alpine`，需安装 `gcompat`（glibc 兼容层），否则 `protoc-gen-grpc-java`（编译为 glibc）无法在 Alpine (musl) 上运行。
- **运行阶段**：`amazoncorretto:17-alpine`，`eclipse-temurin` 镜像在国内 registry 镜像环境下可能无法拉取（`content size of zero`），`amazoncorretto` 可作为替代。
- **非 root 用户**：以 `rag:rag` (1000:1000) 运行。

**本地构建**（无需 Docker）：

```bash
mvn clean package -DskipTests
java -jar target/rag-server-1.0.0-SNAPSHOT.jar --spring.profiles.active=dev
```

### 3.2 Python AI 服务（rag-python）

Dockerfile 位于 `RAG-PYTHON/docker/Dockerfile`。

**关键构建要点**：

- **基础镜像**：`python:3.11-alpine`，Debian 系镜像可能因 registry 问题无法拉取。
- **PyTorch**：必须从 `https://download.pytorch.org/whl/cpu` 安装（提供 musllinux wheel），PyPI 无 musl 版本。必须在其他依赖（如 sentence-transformers）之前安装。
- **Proto 编译**：构建时执行 `scripts/compile_proto.py`，脚本会自动修复生成文件中的导入路径。

详见 [RAG-PYTHON README](../RAG-PYTHON/README.md)。

## 四、环境变量详解

### Java 服务环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `SPRING_PROFILES_ACTIVE` | prod | Spring Profile |
| `SPRING_DATASOURCE_URL` | — | 完整 JDBC URL |
| `SPRING_DATASOURCE_USERNAME` | root | 数据库用户名 |
| `SPRING_DATASOURCE_PASSWORD` | root123 | 数据库密码 |
| `SPRING_DATA_REDIS_HOST` | redis | Redis 地址 |
| `SPRING_DATA_REDIS_PORT` | 6379 | Redis 端口 |
| `SPRING_DATA_REDIS_PASSWORD` | redis123 | Redis 密码 |
| `SPRING_KAFKA_BOOTSTRAP_SERVERS` | kafka:9092 | Kafka 地址 |
| `MINIO_ENDPOINT` | http://minio:9000 | MinIO（Java SDK 需 `http://` 前缀） |
| `MINIO_ACCESS_KEY` | minioadmin | MinIO AccessKey |
| `MINIO_SECRET_KEY` | minioadmin123 | MinIO SecretKey |
| `GRPC_RETRIEVAL_HOST` | rag-python | 检索服务地址 |
| `GRPC_RETRIEVAL_PORT` | 50051 | 检索服务端口 |
| `GRPC_GENERATION_HOST` | rag-python | 生成服务地址 |
| `GRPC_GENERATION_PORT` | 50052 | 生成服务端口 |
| `JWT_SECRET` | — | JWT 签名密钥（生产必改） |

### JDBC URL 注意事项

JDBC URL 中的 `characterEncoding` 必须使用 Java 标准名称 `UTF-8`（非 `utf8mb4`）：
```
jdbc:mysql://mysql:3306/rag_db?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
```

`allowPublicKeyRetrieval=true` 是 MySQL 8.0 `caching_sha2_password` 认证所必需的。

## 六、启动顺序

`docker-compose up -d` 已通过 `depends_on` + `healthcheck` 自动编排，顺序为：

1. MySQL、Redis、MinIO、etcd（并行）
2. MinIO-init（创建 bucket）→ 完成后 Milvus 启动
3. Kafka（并行）
4. rag-python（等待 Kafka + Milvus 健康）
5. rag-server（等待所有服务健康）

## 七、常见问题

### Java 服务

| 问题 | 原因 | 解决 |
|------|------|------|
| `Unsupported character encoding 'utf8mb4'` | JDBC URL 使用了 MySQL 字符集名而非 Java 标准名 | 改为 `characterEncoding=UTF-8` |
| `Public Key Retrieval is not allowed` | MySQL 8.0 caching_sha2_password 认证 | JDBC URL 追加 `allowPublicKeyRetrieval=true` |
| `/actuator/health` 返回 403 | Spring Security 拦截 | SecurityConfig 添加 `.requestMatchers("/actuator/health").permitAll()` |
| 登录 `密码错误` | BCrypt 哈希与密码不匹配 | 重新生成 BCrypt 哈希更新数据库 |
| 构建时 `protoc-gen-grpc-java` 错误 | Alpine musl 不兼容 glibc 二进制 | Dockerfile 添加 `apk add --no-cache gcompat` |
| `eclipse-temurin` 镜像无法拉取 | Registry 镜像问题 | 使用 `amazoncorretto:17-alpine` 替代 |

### Python 服务

| 问题 | 原因 | 解决 |
|------|------|------|
| `sentence-transformers` 安装失败 | 依赖 torch 但 PyPI 无 musl wheel | 先 `pip install torch --index-url https://download.pytorch.org/whl/cpu` |
| `No module named 'retrieval_pb2'` | Proto 生成代码使用绝对导入 | compile_proto.py 自动修复导入路径 |
| `KeyError: 'task_id'` | Loguru 格式中的 extra 字段无默认值 | `logger.configure(extra={"task_id": ""})` |
| MinIO `path in endpoint is not allowed` | Python minio SDK 不接受 `http://` 前缀 | 使用 `minio:9000`（与 Java 相反） |
| `KeyError: 'server'` | 配置键路径错误 | `get_config()['server']['host']`，非 `cfg['server']['host']` |

### Milvus

| 问题 | 原因 | 解决 |
|------|------|------|
| `Endpoint url cannot have fully qualified paths` | Milvus 2.6 拒绝 `http://` 前缀的 MINIO_ADDRESS | 使用 `minio:9000` 而非 `http://minio:9000` |

## 八、生产环境建议

1. **MySQL**：至少主从复制，数据盘 SSD，定期备份
2. **Redis**：哨兵/集群模式，开启 AOF 持久化
3. **Kafka**：3 节点集群，replication factor ≥ 2
4. **MinIO**：分布式模式（4 节点起步），纠删码容错
5. **Milvus**：集群模式，etcd 高可用
6. **Java 应用**：至少 2 实例 + Nginx 负载均衡
7. **日志**：接入 ELK/Loki 集中收集
8. **监控**：Prometheus + Grafana，关键指标：QPS、延迟、错误率、JVM 堆内存
9. **JVM 参数建议**：
   ```
   -Xms1024m -Xmx2048m
   -XX:+UseG1GC
   -XX:MaxGCPauseMillis=200
   -XX:+HeapDumpOnOutOfMemoryError
   ```

## 九、常用运维命令

```bash
# 查看所有容器状态
docker ps --format "table {{.Names}}\t{{.Status}}"

# 查看指定服务日志
docker logs -f rag-server
docker logs -f rag-python

# 重启单个服务
docker-compose restart rag-server

# 重新构建并启动
docker-compose up -d --build rag-server

# 数据库备份
docker exec rag-mysql mysqldump -u root -proot123 rag_db > rag_db_backup_$(date +%Y%m%d).sql

# 进入容器调试
docker exec -it rag-server sh
docker exec -it rag-mysql mysql -u root -proot123 rag_db

# 清理未使用资源
docker system prune -a
```
