# RAG 知识库系统 — 单服务器部署文档

## 一、云服务器要求

### 1.1 最低配置

| 资源 | 最低 | 推荐 |
|------|------|------|
| CPU | 4 核 | 8 核 |
| 内存 | 16 GB | 32 GB |
| 磁盘 | 50 GB SSD | 100 GB SSD |
| 操作系统 | Ubuntu 22.04 / CentOS 7.9 | Ubuntu 22.04 |
| 带宽 | 5 Mbps | 10 Mbps+ |

### 1.2 环境依赖

| 组件 | 版本 | 用途 |
|------|------|------|
| Docker | 24.0+ | 容器运行时 |
| Docker Compose | 2.20+ | 多容器编排 |
| Git | 2.x | 代码拉取 |

全部中间件和服务均已容器化，**无需本地安装** Java/Python/MySQL/Redis/Kafka/MinIO/Milvus。

                    │    ├─ /       → Vue 前端  │
                    │    └─ /api/*  → Java 后端 │
                    └──────────┬───────────────┘
                               │
              ┌────────────────┼────────────────────┐
              │                │                    │
    ┌─────────▼──────┐  ┌─────▼──────┐  ┌─────────▼──────┐
    │  rag-server    │  │ rag-python │  │  rag-memory    │
    │  Java :8080    │  │ :50051/52  │  │  :50053/54     │
    │  业务控制中心   │  │ AI 计算核心 │  │  用户记忆引擎   │
    └───────┬────────┘  └─────┬──────┘  └───────┬────────┘
            │                 │                  │
            └─────────┬───────┴──────────────────┘
                      │
    ┌─────────────────┼──────────────────────────────┐
    │                 │                              │
    ▼                 ▼                              ▼
  MySQL :3307    Redis :6379    Kafka :9092    MinIO :9000
  (业务数据)      (缓存/锁)      (消息队列)     (对象存储)

    Milvus :19530 ← etcd :2379     rag-cleaning :50056   rag-que :50055
    (向量数据库)    (Milvus元数据)   (文档清洗服务)         (查询优化引擎)

**资源估算**：

| 类别 | 容器 | 内存 |
|------|------|------|
| 基础设施 | MySQL + Redis + Kafka + MinIO + etcd | 3~4 GB |
| 向量数据库 | Milvus standalone | 2~4 GB |
| 业务服务 | Java (rag-server) | 0.5~1 GB |
| AI 服务 | Python × 4 (python/memory/que/cleaning) | 2~4 GB |
| Web 服务 | Nginx | ~100 MB |
| 系统预留 | OS 自身 | ~1 GB |
| **合计** | | **10~14 GB** |

## 三、服务器初始化

### 3.1 安装 Docker

```bash
# Ubuntu 22.04
sudo apt update && sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

退出 SSH 重新登录使 `docker` 免 sudo 生效。

### 3.2 配置防火墙

```bash
# 开放必要端口
sudo ufw allow 22/tcp      # SSH
sudo ufw allow 80/tcp      # Nginx (前端 + API 代理)
sudo ufw enable
```

其他端口（8080/50051-50056/9000/9001/9092/3307/19530）**仅容器间通信，不对外开放**。

云服务器还需要在**安全组**中放行 `22` 和 `80` 端口（其余端口不要开放）。

### 3.3 调整系统参数

```bash
# 增加虚拟内存区域（Milvus 需要）
sudo sysctl -w vm.max_map_count=262144
echo "vm.max_map_count=262144" | sudo tee -a /etc/sysctl.conf

# 调大文件句柄限制
echo "* soft nofile 65536" | sudo tee -a /etc/security/limits.conf
echo "* hard nofile 65536" | sudo tee -a /etc/security/limits.conf
```

## 七、配置 Nginx 代理前端

### 7.1 安装 Nginx

```bash
sudo apt install -y nginx
```

### 7.2 创建 Nginx 配置

```bash
sudo cat > /etc/nginx/sites-available/rag << 'EOF'
server {
    listen 80;
    server_name _;

    # 前端静态文件
    root /opt/rag/RAG-Web/dist;
    index index.html;

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式问答需要关闭缓冲
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;

        # 上传大文件
        client_max_body_size 100m;
    }

    # Vue Router history 模式
    location / {
        try_files $uri $uri/ /index.html;
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/rag /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 7.3 访问系统

浏览器打开 `http://<服务器公网IP>`，使用默认账号登录。

## 十、常见问题及处理

### 10.1 构建阶段

| 问题 | 原因 | 解决 |
|------|------|------|
| `eclipse-temurin` 镜像无法拉取 | Registry 镜像问题 | 已改用 `amazoncorretto:17-alpine` |
| `sentence-transformers` 安装失败 | PyTorch 无 musl wheel | Dockerfile 中先安装 PyTorch CPU 版本 |
| HuggingFace 模型下载失败 | 国内网络不通 | `HF_ENDPOINT=https://hf-mirror.com` 已配置 |
| `protoc-gen-grpc-java` 报错 | Alpine musl vs glibc | Dockerfile 中 `apk add gcompat` 已处理 |

### 10.2 运行时

| 问题 | 原因 | 解决 |
|------|------|------|
| Kafka 消费者收不到消息 | KRaft `__consumer_offsets` 副本因子=3 | 手动创建 topic 或确保 `KAFKA_NUM_PARTITIONS` 已配置 |
| 中文乱码 | MySQL 字符集链路不一致 | JDBC URL 配置 `characterEncoding=UTF-8` + MySQL `--skip-character-set-client-handshake` |
| 容器启动失败 `permission denied` | 非 root 用户无写权限 | Dockerfile 已 `chown -R rag:rag` 处理 |
| MinIO `NoSuchKey` | 路径重复拼接 bucket 前缀 | Python 端自动去重 `_strip_bucket_prefix()` |
| Milvus `vm.max_map_count` 不足 | 系统默认值过低 | `sysctl -w vm.max_map_count=262144` |
| 检索返回空结果 | L2 距离过滤方向/阈值不当 | 已改为相似度过滤，阈值 0.3 |
| 容器重启后 BM25 失效 | 内存索引未持久化 | 已知限制，定期全量 EMBED_PROCESS 可恢复 |

### 10.3 前端

| 问题 | 原因 | 解决 |
|------|------|------|
| 刷新页面出现 404 | Vue Router history 模式 | Nginx 已配置 `try_files $uri /index.html` |
| SSE 问答中断 | Nginx 代理缓冲 | `proxy_buffering off` 已配置 |
| 文件下载 blob 处理错误 | Axios 拦截器破坏 blob 响应 | 已修复：blob/text 类型直接返回原始数据 |

## 十一、内存不足时的精简方案

如果服务器内存只有 8~12 GB，可以采取以下措施：

### 11.1 减少 Java 堆内存

修改 `RAG-BACKEND/docker/Dockerfile` 的 `JAVA_OPTS` 默认值，或在 `.env` 添加：
```bash
JAVA_OPTS="-Xms256m -Xmx512m -XX:+UseG1GC"
```

在 `RAG-BACKEND/docker-compose.yml` 的 `rag-server` 服务中添加：
```yaml
environment:
  JAVA_OPTS: "-Xms256m -Xmx512m"
```

### 11.2 限制 Milvus 内存

在 docker-compose.yml 的 `milvus` 服务添加：
```yaml
deploy:
  resources:
    limits:
      memory: 2g
```

### 11.3 减少 Python 服务数量

暂时不部署 `rag-memory` 和 `rag-que`，只保留核心服务：
```bash
docker compose up -d --build mysql redis kafka minio minio-init etcd milvus rag-python rag-server
```

代价：失去记忆管理和查询优化功能。

### 11.4 使用外部 LLM Embedding API

如果本地 embedding 模型（BAAI/bge-base-zh-v1.5）占用内存过大，可配置使用远程 embedding API，去掉 Dockerfile 中的模型预下载步骤。

## 十二、生产环境升级建议

当系统需要正式上线时，建议逐步升级：

1. **数据库分离**：MySQL/Redis 使用云服务商托管版本，自动备份和主从
2. **Kafka 集群**：3 节点，replication factor ≥ 2
3. **MinIO 分布式**：4 节点起步，纠删码容错
4. **Milvus 集群**：读写分离 + etcd 高可用
5. **Java 多实例**：2 实例 + Nginx 负载均衡
6. **日志收集**：接入 ELK / Loki
7. **监控告警**：Prometheus + Grafana，关注 QPS、延迟、错误率、JVM 堆内存、Milvus 查询延迟
8. **定期备份**：数据库每日备份 + MinIO 数据异地同步
9. **HTTPS**：Nginx 配置 Let's Encrypt 证书
