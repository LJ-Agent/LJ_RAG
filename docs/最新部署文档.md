## 2. 混合部署架构：一套代码，两种模式

### 2.1 设计原理

RAG-BACKEND 采用 **Spring Profile + 共享 JAR** 的方式实现单体和微服务的无缝切换。

```
                     rag-server:latest (同一个 Docker 镜像)
                              │
            ┌─────────────────┼─────────────────┐
            │                 │                 │
    无 Profile            Profile=auth      Profile=kb
    加载全部Controller    只加载Auth相关     只加载KB相关
            │                 │                 │
    单体 :8080          微服务 :8081       微服务 :8082
```

**核心机制**：13 个 Controller 全部标注 `@Profile` 注解

```java
// AuthController.java
@Profile("auth")
@RestController
public class AuthController { ... }

// FileController.java
@Profile("doc")
@RestController
public class FileController { ... }
```

- **不加 Profile**：Spring 加载全部 Controller → 单体模式
- **加 Profile=auth**：Spring 只加载 `@Profile("auth")` 的 Bean → 微服务模式

### 2.2 两种模式对比

| 维度 | 单体模式 | 微服务模式 |
|------|----------|------------|
| 容器数 | 1 个 (rag-server) | 5 个 (rag-auth/kb/doc/qa/config) |
| 内存 | ~700MB | ~700MB × 5 |
| 端口 | :8080 | :8081~:8085 |
| 故障隔离 | ❌ 单点 | ✅ 独立 |
| 独立扩缩 | ❌ | ✅ |
| 部署复杂度 | 低 | 中 |
| 适用场景 | 开发/小规模 | 生产/大规模 |
| Profile | 无 (default) | auth/kb/doc/qa/config |

### 2.3 部署切换

**单体 → 微服务**：无需改代码，只需启动时指定 Profile

```bash
# 单体 (默认)
docker run -d --name rag-server rag-server:latest

# 微服务 (同一镜像, 不同参数)
docker run -d --name rag-auth -e SPRING_PROFILES_ACTIVE=auth rag-server:latest
docker run -d --name rag-kb   -e SPRING_PROFILES_ACTIVE=kb   rag-server:latest
docker run -d --name rag-doc  -e SPRING_PROFILES_ACTIVE=doc  rag-server:latest
docker run -d --name rag-qa   -e SPRING_PROFILES_ACTIVE=qa   rag-server:latest
docker run -d --name rag-config -e SPRING_PROFILES_ACTIVE=config rag-server:latest
```

**微服务 → 单体**：停掉微服务容器，启动不加 Profile 的单体容器即可。

### 2.4 开发建议

| 阶段 | 推荐模式 | 原因 |
|------|----------|------|
| 本地开发 | 单体 | 启动快，调试方便 |
| 功能测试 | 单体 | 全功能可用 |
| 集成测试 | 微服务 | 验证隔离性 |
| 生产部署 | 微服务 | 故障隔离，独立扩缩容 |

## 4. 快速部署（单体模式）

```bash
# 1. 克隆代码
git clone https://gitee.com/yangchangling/rag-basic-platform.git
cd rag-basic-platform

# 2. 切换分支
cd RAG-BACKEND && git checkout master_backend
cd ../RAG-PYTHON && git checkout master_python
cd ../RAG-Web && git checkout master_front
cd ../RAG-BACKEND

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env 填入 LLM_API_KEY 等

# 4. 一键启动 (14 容器)
docker compose up -d

# 5. 等待所有服务 healthy (约3分钟)
docker ps --filter name=rag --filter health=healthy

# 6. 启动前端
cd ../RAG-Web && npm install && npm run dev

# 7. 访问
# 前端:     http://localhost:5173
# API:      http://localhost:8080
# Swagger:  http://localhost:8080/swagger-ui.html
# Nacos:    http://localhost:8848/nacos (nacos/nacos)
# 账号:     admin / admin123
```

## 5. 完整部署（含 Gateway + 监控）

### 4.1 启动核心服务

```bash
cd RAG-BACKEND
docker compose up -d
# 启动: mysql, redis, kafka, minio, etcd, milvus, nacos, rag-python, rag-server
```

### 4.2 启动 Gateway

```bash
docker run -d --name rag-gateway \
  --network rag-network \
  -p 8088:8080 \
  -e JWT_SECRET=your-256-bit-secret-key-change-in-production \
  -e REDIS_HOST=redis \
  -e REDIS_PASSWORD=redis123 \
  rag-gateway:latest
```

### 4.3 启动监控栈

```bash
docker compose -f docker-compose-monitoring.yml up -d
# 启动: loki, prometheus, grafana
```

### 4.4 启动微服务（内存充足时）

```bash
# 每个微服务独立启动（共享 rag-server 镜像，不同 Profile）
for svc in "rag-auth:8081:auth" "rag-kb:8082:kb" "rag-doc:8083:doc" "rag-qa:8084:qa" "rag-config:8085:config"; do
  IFS=':' read -r name port profile <<< "$svc"
  docker run -d --name $name --network rag-network -p $port:$port \
    -e "SPRING_PROFILES_ACTIVE=$profile" \
    -e MYSQL_HOST=mysql -e MYSQL_PASSWORD=root123 \
    -e REDIS_HOST=redis -e REDIS_PASSWORD=redis123 \
    -e KAFKA_BOOTSTRAP_SERVERS=kafka:9092 \
    -e "MINIO_ENDPOINT=http://minio:9000" \
    -e MINIO_ACCESS_KEY=minioadmin -e MINIO_SECRET_KEY=minioadmin123 \
    -e JWT_SECRET=your-256-bit-secret-key-change-in-production \
    -e NACOS_SERVER_ADDR=nacos:8848 \
    rag-server:latest
done
```

## 10. 常见问题

**Q: Gateway 启动后 API 返回 401**
A: 检查 JWT_SECRET 与 rag-server 一致

**Q: 微服务容器 Exited (1)**
A: 内存不足，减少并发启动数量，逐个启动

**Q: Nacos 服务列表为空**
A: 等待服务心跳注册（首次约 30s），检查 NACOS_SERVER_ADDR 配置

**Q: Kafka 连接失败**
A: 确认 KRaft 模式配置正确，检查 KAFKA_ADVERTISED_LISTENERS
