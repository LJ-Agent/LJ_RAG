## 2. 混合部署架构：一套代码，两种模式

### 2.1 设计原理

RAG-BACKEND 采用 **Maven 多模块 + Spring Profile** 实现单体和微服务的无缝切换。

**纯微服务模块结构，一份代码，无重复**：

```
RAG-BACKEND/
├── pom.xml                   ← 父POM (packaging=pom, 管理7个子模块)
├── rag-common/    (87 files) ← 共享层: Entity/Mapper/Infra/Common
├── rag-auth/      (10 files) ← 认证: Auth/User/Role Controller + Service
├── rag-kb/        (9 files)  ← 知识库: KB/Team Controller + Service
├── rag-doc/       (15 files) ← 文档: File/Chunk/Review Controller + Service
├── rag-qa/        (13 files) ← 问答: QA/Feedback Controller + Service
├── rag-config/    (5 files)  ← 配置: SystemConfig/UserConfig Controller + Service
└── rag-monolith/  (1 file)   ← 聚合模块: 依赖全部→单体JAR
```

**核心机制**：

1. **rag-common**：共享层，包含所有 Entity、Mapper、Infrastructure、Common 工具类
2. **业务模块**：各自含专属 Controller + Service + DTO，依赖 `rag-common`
3. **rag-monolith**：聚合所有模块，构建单体 JAR
4. **Profile 注解**：13 个 Controller 标注 `@Profile({"xxx", "prod"})`，控制加载范围

```java
// AuthController.java — 同时支持单体和微服务
@Profile({"auth", "prod"})  // prod=单体加载, auth=微服务auth模块加载
@RestController
public class AuthController { ... }
```

- **SPRING_PROFILES_ACTIVE=prod**：匹配所有 `@Profile({..., "prod"})` → 单体模式
- **SPRING_PROFILES_ACTIVE=auth**：仅匹配 `@Profile({"auth", "prod"})` → 微服务auth模块

### 2.2 两种模式对比

| 维度 | 单体模式 | 微服务模式 |
|------|----------|------------|
| 构建命令 | `mvn package` | `mvn package -pl rag-auth -am` |
| 容器数 | 1 个 (rag-server) | 5 个 (rag-auth/kb/doc/qa/config) |
| 内存 | ~700MB | ~700MB × 5 |
| 端口 | :8080 | :8081~:8085 |
| Profile | `prod` | `auth`/`kb`/`doc`/`qa`/`config` |
| 故障隔离 | ❌ 单点 | ✅ 独立 |
| 独立扩缩 | ❌ | ✅ |
| 部署复杂度 | 低 | 中 |
| 当前状态 | ✅ 已验证 | ⏳ 代码就绪 |

### 2.3 实际部署命令

**单体模式（当前运行）**：
```bash
cd RAG-BACKEND
docker compose up -d --build rag-server
# SPRING_PROFILES_ACTIVE=prod → 所有Controller加载
```

**微服务模式（需16GB+内存）**：
```bash
# 每个微服务共享 rag-server:latest 镜像，不同 Profile
docker run -d --name rag-auth --network rag-network -p 8081:8080 \
  -e SPRING_PROFILES_ACTIVE=auth [其他env...] rag-server:latest
# 同理启动 rag-kb, rag-doc, rag-qa, rag-config
```

### 2.4 关键经验

1. **Profile 必须匹配运行环境**：容器 `SPRING_PROFILES_ACTIVE=prod`，则 `@Profile` 必须包含 `"prod"`
2. **role_permissions 数据保护**：重建容器时确保权限数据不丢失
3. **源码双份维护**：`src/`（单体）+ `rag-common/src/`（微服务共享层）
4. **单体优先**：开发测试用单体，生产扩展用微服务

## 4. 快速部署（单体模式）

```bash
# 1. 克隆代码
git clone https://gitee.com/yangchangling/rag-basic-platform.git
cd rag-basic-platform

# 2. 切换分支
cd RAG-BACKEND && git checkout master_backend
cd ../RAG-PYTHON && git checkout master_python
cd ../RAG-Web && git checkout master_front
cd ../RAG-BACKEND

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env 填入 LLM_API_KEY 等

# 4. 一键启动 (14 容器)

# 5. 等待所有服务 healthy (约3分钟)
docker ps --filter name=rag --filter health=healthy

# 6. 启动前端
cd ../RAG-Web && npm install && npm run dev

# 7. 访问
# 前端:     http://localhost:5173

# Swagger:  http://localhost:8080/swagger-ui.html
# Nacos:    http://localhost:8848/nacos (nacos/nacos)
```

## 5. 完整部署（含 Gateway + 监控）

### 4.1 启动核心服务

```bash
cd RAG-BACKEND
docker compose up -d
# 启动: mysql, redis, kafka, minio, etcd, milvus, nacos, rag-python, rag-server
```

### 4.2 启动 Gateway

```bash
docker run -d --name rag-gateway \
  --network rag-network \
  -p 8088:8080 \
  -e JWT_SECRET=your-256-bit-secret-key-change-in-production \
  -e REDIS_HOST=redis \
  -e REDIS_PASSWORD=redis123 \
  rag-gateway:latest
```

### 4.3 启动监控栈

```bash
docker compose -f docker-compose-monitoring.yml up -d
# 启动: loki, prometheus, grafana
```

### 4.4 启动微服务（内存充足时）

```bash
# 每个微服务独立启动（共享 rag-server 镜像，不同 Profile）
for svc in "rag-auth:8081:auth" "rag-kb:8082:kb" "rag-doc:8083:doc" "rag-qa:8084:qa" "rag-config:8085:config"; do
  IFS=':' read -r name port profile <<< "$svc"
  docker run -d --name $name --network rag-network -p $port:$port \
    -e "SPRING_PROFILES_ACTIVE=$profile" \
    -e MYSQL_HOST=mysql -e MYSQL_PASSWORD=root123 \
    -e REDIS_HOST=redis -e REDIS_PASSWORD=redis123 \
    -e KAFKA_BOOTSTRAP_SERVERS=kafka:9092 \
    -e "MINIO_ENDPOINT=http://minio:9000" \
    -e MINIO_ACCESS_KEY=minioadmin -e MINIO_SECRET_KEY=minioadmin123 \
    -e JWT_SECRET=your-256-bit-secret-key-change-in-production \
    -e NACOS_SERVER_ADDR=nacos:8848 \
    rag-server:latest
done
```

## 10. 常见问题

**Q: Gateway 启动后 API 返回 401**
A: 检查 JWT_SECRET 与 rag-server 一致

**Q: 微服务容器 Exited (1)**
A: 内存不足，减少并发启动数量，逐个启动

**Q: Nacos 服务列表为空**
A: 等待服务心跳注册（首次约 30s），检查 NACOS_SERVER_ADDR 配置

**Q: Kafka 连接失败**
A: 确认 KRaft 模式配置正确，检查 KAFKA_ADVERTISED_LISTENERS
