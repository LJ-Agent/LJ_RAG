## 一、数据库概览

| 项目 | 说明 |
|------|------|
| 数据库名称 | `rag_db` |

## 三、完整表结构

### 3.1 用户表 `users`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 用户ID |
| username | VARCHAR(64) | NOT NULL, UNIQUE | 用户名 |
| password_hash | VARCHAR(256) | NOT NULL | BCrypt密码哈希 |
| real_name | VARCHAR(64) | NULL | 真实姓名 |
| email | VARCHAR(128) | NULL | 邮箱 |
| phone | VARCHAR(20) | NULL | 手机号 |
| avatar_url | VARCHAR(512) | NULL | 头像URL |
| status | TINYINT | NOT NULL, DEFAULT 1 | 0=禁用, 1=正常 |
| last_login_at | DATETIME | NULL | 最后登录时间 |
| last_login_ip | VARCHAR(64) | NULL | 最后登录IP |
| created_at | DATETIME | NOT NULL, DEFAULT NOW() | 创建时间 |
| updated_at | DATETIME | NOT NULL, ON UPDATE NOW() | 更新时间 |
| deleted | TINYINT | NOT NULL, DEFAULT 0 | 逻辑删除 |

**索引：**
- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_username` (`username`)
- KEY `idx_status` (`status`)
- KEY `idx_created_at` (`created_at`)

### 3.7 文档表 `documents`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 文档ID |
| kb_id | BIGINT | NOT NULL | 所属知识库ID |
| file_name | VARCHAR(256) | NOT NULL | 原始文件名 |
| file_type | VARCHAR(32) | NOT NULL | 文件扩展名 |
| file_size | BIGINT | NOT NULL | 文件大小(字节) |
| file_md5 | VARCHAR(64) | NOT NULL, UNIQUE | 文件MD5哈希 |
| minio_path | VARCHAR(512) | NOT NULL | MinIO存储路径 |
| status | VARCHAR(32) | NOT NULL, DEFAULT 'UPLOADED' | 文档状态 |
| error_message | TEXT | NULL | 失败原因 |
| chunk_count | INT | DEFAULT 0 | 分块数量 |
| upload_user_id | BIGINT | NOT NULL | 上传者ID |
| upload_at | DATETIME | NOT NULL | 上传时间 |
| completed_at | DATETIME | NULL | 处理完成时间 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |
| deleted | TINYINT | NOT NULL, DEFAULT 0 | 逻辑删除 |

**索引：**
- PRIMARY KEY (`id`)
- UNIQUE KEY `uk_file_md5` (`file_md5`)
- KEY `idx_kb_id` (`kb_id`)
- KEY `idx_status` (`status`)
- KEY `idx_upload_user_id` (`upload_user_id`)
- KEY `idx_created_at` (`created_at`)

**status字段取值（文档状态机）：**

| 状态值 | 说明 | 后续状态 |
|--------|------|----------|
| UPLOADED | 已上传 | → PARSING |
| PARSING | 解析中（Python处理） | → CLEANING / PARSING_FAILED |
| CLEANING | 清洗中（Python处理） | → PENDING_REVIEW / CLEANING_FAILED |
| PENDING_REVIEW | 待人工审核 | → APPROVED / REJECTED |
| APPROVED | 审核通过 | → CHUNKING |
| REJECTED | 审核驳回 | → PARSING（重新处理） |
| CHUNKING | 分块中（Python处理） | → EMBEDDING / CHUNKING_FAILED |
| EMBEDDING | 向量化中（Python处理） | → COMPLETED / EMBEDDING_FAILED |
| COMPLETED | 处理完成 | 终态 |
| *_FAILED | 处理失败 | → 对应处理阶段（重试） |

## 五、设计规范

1. **主键策略**：所有表使用 `BIGINT AUTO_INCREMENT` 作为主键
2. **时间字段**：`created_at` 和 `updated_at` 使用 DATETIME 类型，由数据库自动维护
3. **逻辑删除**：业务表使用 `deleted` 字段（0=正常, 1=已删），关联表不使用逻辑删除
4. **字符集**：统一 utf8mb4，支持 emoji 和特殊字符
5. **索引设计**：高频查询字段建立索引，唯一字段建立唯一索引
6. **大字段分离**：TEXT/MEDIUMTEXT/LONGTEXT 字段在不同行独立存储
7. **分表预留**：`documents` 和 `chat_records` 按时间分表预留（高频写入）
8. **命名规范**：表名使用小写蛇形命名法(snake_case)，字段名同理
