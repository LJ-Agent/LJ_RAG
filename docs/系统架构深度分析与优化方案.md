# RAG 系统架构深度分析与优化方案

> 分析日期: 2026-06-01 | 当前版本: v2.0 (微服务改造后)

---

## 2. 架构层面问题分析

### 2.1 Nacos 资源浪费 (优先级: 🔴高)

**问题**: Nacos 默认 JVM 堆 1GB, 仅注册 3 个服务, 严重浪费。

**优化**:
```yaml
# docker-compose.yml
nacos:
  environment:
    - JVM_XMS=256m
    - JVM_XMX=512m     # 从 1GB 降到 512MB
    - JVM_XMN=128m
```
**预计节省**: ~500MB 内存

### 2.2 微服务容器未独立部署 (优先级: 🔴高)

**问题**: 已拆分 5 个 Maven 模块但未实际运行, 单体 rag-server 承载全部流量。

**优化**: 各模块独立构建 Docker 镜像并部署。

### 2.3 Kafka Topic 冗余 (优先级: 🟡中)

**问题**: 22 个 topic, 但 rag-cleaning 的 Kafka consumer 组经常离线。

**优化**: 清理未使用的 topic, 确保消费者组稳定运行。

### 2.4 数据库空表清理 (优先级: 🟢低)

**问题**: 20 张表中有 8 张完全空表 (user_configs, atomic_facts 等)。

**优化**: 按需保留, 未使用的表可归档。

### 2.5 日志未集中管理 (优先级: 🟡中)

**问题**: 12 个容器各自输出日志到 stdout, 无集中采集。

**优化**: 引入 ELK/Loki 日志中心, 或至少 Docker logging driver 集中输出。

### 2.6 健康检查与监控缺失 (优先级: 🟡中)

**问题**: 无统一监控面板, 服务宕机依赖 Docker restart。

**优化**: Prometheus + Grafana 监控面板。

### 2.7 配置管理碎片化 (优先级: 🟡中)

**问题**: 配置分散在 YAML + DB + env, Nacos 配置中心未启用。

**优化**: 将 system_configs 表数据迁移到 Nacos Config。

## 3. 优化实施

### 3.1 Nacos JVM 降配

```yaml
nacos:
  environment:
    - JVM_XMS=256m
    - JVM_XMX=512m
    - JVM_XMN=128m
```

### 3.2 微服务独立部署

每个模块需要独立的 Dockerfile 和 CI/CD 构建流程。

### 3.3 关键优化清单

| 优化项 | 影响 | 工作量 | 优先级 |
|--------|------|--------|:---:|
| Nacos JVM 降配 | 省 500MB 内存 | 5 分钟 | 🔴 |
| 微服务独立部署 | 真正微服务化 | 2 天 | 🔴 |
| Kafka Topic 清理 | 减少维护负担 | 30 分钟 | 🟡 |
| 配置迁移 Nacos | 统一配置管理 | 1 天 | 🟡 |
| 日志集中 | 运维可视化 | 1 天 | 🟡 |
| 监控面板 | 故障快速发现 | 1 天 | 🟡 |
| 空表清理 | 数据库整洁 | 10 分钟 | 🟢 |
