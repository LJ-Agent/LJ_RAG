# 系统配置可视化编辑 — 架构设计文档

> 目标：将所有系统配置参数迁移到 Web 管理界面统一管理，支持在线编辑、即时生效、变更审计。

---

## 1. 总体架构

```
┌─────────────────────────────────────────────────────┐
│                   RAG-Web 管理前端                    │
│   ┌─────────────────────────────────────────────┐   │
│   │  系统配置页面：分类 Tab + 动态表单 + 实时预览  │   │
│   └─────────────────────────────────────────────┘   │
└──────────────────────┬──────────────────────────────┘
                       │ REST API (CRUD + Publish)
┌──────────────────────▼──────────────────────────────┐
│                 RAG-BACKEND (Java)                   │
│  ┌──────────────────────────────────────────────┐   │
│  │  ConfigController  —  CRUD 接口               │   │
│  │  ConfigService     —  校验/版本/灰度          │   │
│  │  ConfigPublisher   —  发布变更事件到 Kafka    │   │
│  └──────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────┐   │
│  │  system_configs 表 (MySQL)                    │   │
│  └──────────────────────────────────────────────┘   │
└──────────────────────┬──────────────────────────────┘
                       │ Kafka: rag-config-change
         ┌─────────────┼─────────────┬────────────┐
         ▼             ▼             ▼            ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
   │RAG-PYTHON│ │RAG-CLEAN │ │RAG-MEMORY│ │ RAG-QUE  │
   │Config    │ │Config    │ │Config    │ │Config    │
   │Reloader  │ │Reloader  │ │Reloader  │ │Reloader  │
   └──────────┘ └──────────┘ └──────────┘ └──────────┘
```

### 核心原则

1. **数据库为唯一真相源** — 所有配置存 MySQL `system_configs` 表，废除各服务的 YAML 文件配置
2. **Kafka 事件驱动热生效** — 配置变更后发布事件，各服务监听并动态重载
3. **YAML 文件降级兜底** — 保留文件配置作为初始默认值，DB 无记录时使用文件值
4. **变更可追溯** — 每次修改记录版本历史，支持回滚

## 2. 配置数据模型

### 2.1 核心表：`system_configs`

```sql
CREATE TABLE system_configs (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    config_key      VARCHAR(128)  NOT NULL UNIQUE COMMENT '配置键，如 chunk.default_size',
    config_value    TEXT          NOT NULL COMMENT '配置值（JSON 或标量）',
    value_type      VARCHAR(16)   NOT NULL DEFAULT 'string' COMMENT '类型: string/int/float/bool/json',
    category        VARCHAR(64)   NOT NULL COMMENT '分类: chunk/retrieval/cleaning/llm/...',
    sub_category    VARCHAR(64)   COMMENT '子分类',
    label           VARCHAR(128)  NOT NULL COMMENT '中文显示名',
    description     VARCHAR(512)  COMMENT '参数说明',
    default_value   TEXT          COMMENT '出厂默认值',
    validation_rule VARCHAR(256)  COMMENT '校验规则 JSON: {type, min, max, enum, pattern}',
    required        TINYINT       DEFAULT 0 COMMENT '是否必填',
    sort_order      INT           DEFAULT 0 COMMENT '排序',
    editable        TINYINT       DEFAULT 1 COMMENT '是否允许编辑',
    encrypt         TINYINT       DEFAULT 0 COMMENT '敏感值是否加密存储(如API Key)',
    target_services JSON          COMMENT '影响的微服务列表 ["rag-python","rag-backend"]',
    reload_strategy VARCHAR(32)   DEFAULT 'kafka' COMMENT '生效策略: kafka/restart/api',
    status          VARCHAR(16)   DEFAULT 'active' COMMENT '状态: active/disabled/draft',
    created_at      DATETIME      DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_category (category),
    INDEX idx_target (target_services)
) COMMENT='系统配置参数注册表';
```

### 2.2 版本历史表：`system_config_histories`

```sql
CREATE TABLE system_config_histories (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    config_id       BIGINT        NOT NULL COMMENT '关联 system_configs.id',
    config_key      VARCHAR(128)  NOT NULL,
    old_value       TEXT          COMMENT '变更前的值',
    new_value       TEXT          COMMENT '变更后的值',
    changed_by      BIGINT        COMMENT '修改人用户ID',
    changed_at      DATETIME      DEFAULT CURRENT_TIMESTAMP,

    INDEX idx_config (config_id),
    INDEX idx_time (changed_at)
) COMMENT='配置变更历史（审计追溯）';
```

## 3. 配置加载与热生效机制

### 3.1 配置优先级链

```
编辑后的 DB 值  >  环境变量  >  YAML 文件默认值
   (最高优先)       (中间)        (兜底)
```

### 3.2 Java 端 (RAG-BACKEND)

```java
// ConfigService.java — 配置中心核心

@Service
public class ConfigService {
    
    // 启动时加载全部配置到内存缓存
    private final Map<String, ConfigEntry> configCache = new ConcurrentHashMap<>();
    
    @PostConstruct
    public void init() {
        // 1. 从 DB 加载所有 active 配置
        // 2. 对于 DB 中不存在的 key，从 application.yml 读取作为默认值并写入 DB
        // 3. 构建内存缓存
        refreshAll();
    }
    
    // Kafka 消费者：监听 rag-config-change topic
    @KafkaListener(topics = "rag-config-change")
    public void onConfigChange(ConfigChangeEvent event) {
        // 1. 校验新值合法性
        // 2. 更新内存缓存中的对应 key
        // 3. 热重载受影响的 Bean（如修改了限流参数）
    }
    
    // 获取配置值（供业务代码调用）
    public String getString(String key, String defaultValue) {
        ConfigEntry entry = configCache.get(key);
        return entry != null ? entry.getValue() : defaultValue;
    }
    
    public int getInt(String key, int defaultValue) { ... }
    public boolean getBool(String key, boolean defaultValue) { ... }
    
    // 发布配置变更
    @Transactional
    public void update(String key, String newValue, Long userId) {
        // 1. 校验 + 类型转换
        // 2. 更新 DB
        // 3. 写入 history
        // 4. 更新内存缓存
        // 5. 发送 Kafka 事件
        // 6. 对于 strategy=restart 的 key，标记需要重启
    }
}
```

### 3.3 Python 端 (RAG-PYTHON / CLEANING / MEMORY / QUE)

```python
# common/config_center.py — Python 配置中心客户端

class ConfigCenter:
    """监听 Kafka 配置变更事件，动态更新运行中配置。"""
    
    def __init__(self):
        self._cache: dict[str, Any] = {}
        # 1. 从 DB (通过 gRPC 调用 Java) 加载初始配置
        # 2. 对于 DB 中不存在的 key，从 settings.yaml 读取作为默认值
        self._load_from_db()
        # 3. 启动 Kafka 消费者监听 rag-config-change
        self._start_kafka_listener()
    
    def _on_config_change(self, event: dict):
        key = event["configKey"]
        new_value = event["newValue"]
        reload_strategy = event["reloadStrategy"]
        
        # 更新内存缓存
        self._cache[key] = self._cast_value(new_value, event["valueType"])
        
        if reload_strategy == "restart":
            logger.warning(f"Config '{key}' 需要重启服务才能生效")
        elif reload_strategy == "api":
            # 调用对应的重载接口
            self._reload_component(key)
        # kafka 模式：内存缓存已更新，下次读取自动生效
    
    def _reload_component(self, key: str):
        """针对特殊 key 执行组件级热重载。"""
        if key.startswith("chunk."):
            from ai_core.chunker import reload_chunker
            reload_chunker()  # 重新初始化 SmartChunker 实例
        elif key.startswith("retrieval."):
            from ai_core.retrieval import reload_retrieval
            reload_retrieval()
        # ... 其他组件的重载逻辑
    
    def get(self, key: str, default=None):
        return self._cache.get(key, default)

# 全局单例
config_center = ConfigCenter()
```

### 3.4 生效策略说明

| 策略 | 说明 | 适用配置 |
|------|------|----------|
| `kafka` | Kafka 推送后内存缓存更新，下次调用生效 | 检索参数、分块参数、清洗规则 |
| `restart` | 需要重启服务才能生效（标注警告） | 端口、数据库连接、索引参数 |
| `api` | 通过组件级 API 热重载 | Chunker、Retrieval、QualityValidator |

## 6. 关键设计决策

### 6.1 为什么用 MySQL + Kafka 而不是 Nacos/Apollo？

| 方案 | 优势 | 劣势 |
|------|------|------|
| MySQL + Kafka (**选用**) | 零额外依赖，复用现有基础设施 | 需要自行实现热重载逻辑 |
| Nacos / Apollo | 开箱即用的配置中心 | 新增基础设施依赖，增加运维复杂度 |
| Etcd / Consul | 强一致性 | 需要额外集群，过度设计 |

对于已有 MySQL + Kafka 的系统，自建配置中心是最小成本的方案。

### 6.2 配置回滚

每次发布记录 `system_config_histories`，支持一键回滚到历史任一版本：

1. 用户在历史列表中选择回滚目标版本
2. 后端将 `config_value` 恢复为目标版本的值
3. 重新触发 Kafka 配置变更事件
4. 所有服务重载配置，回到历史状态

### 6.3 灰度发布

对于高风险配置（如 LLM 模型切换），支持按知识库或用户维度灰度：

```sql
-- 扩展 system_configs 增加灰度支持
ALTER TABLE system_configs ADD COLUMN gray_enabled TINYINT DEFAULT 0;
ALTER TABLE system_configs ADD COLUMN gray_rule JSON COMMENT '{"type":"kb_ids","values":[1,2,3]}';
```

非灰度流量继续使用旧配置值，灰度流量使用新值，验证无误后全量发布。

### 6.4 敏感配置保护

带有 `encrypt=1` 标记的配置（如 LLM API Key）：
- 前端显示为 `****`，编辑时需二次确认
- 数据库存储 AES-256 加密后的值
- 仅 `system_configs` 表中标记，解密后传递给微服务

### 6.5 不同生效策略的 UX 提示

| 策略 | 前端提示 | 用户操作 |
|------|----------|----------|
| `kafka` | 绿色「修改即时生效」 | 保存即发布 |
| `api` | 黄色「组件重载后生效 (约 2-5 秒)」 | 保存后自动调用重载 API |
| `restart` | 红色「需重启对应服务」+ 受影响服务列表 | 保存后提示用户手动重启 |

## 7. 实施步骤

### Phase 1：配置注册（1-2 天）
1. 创建 `system_configs` 和 `system_config_histories` 表
2. 初始化脚本：将现有 YAML 配置导入 DB
3. Java `ConfigService` 基础 CRUD + 缓存

### Phase 2：Java 端接入（2-3 天）
1. 替换 `@Value` 注解为 `ConfigService.get()` 调用
2. 实现 Kafka 配置变更事件发布和消费
3. 配置变更历史 + 回滚

### Phase 3：Python 端接入（2-3 天）
1. `ConfigCenter` 客户端实现
2. 替换 `settings.yaml` 读取为 `ConfigCenter.get()`
3. 各组件热重载方法实现

### Phase 4：前端页面（2-3 天）
1. 配置列表页面（分类 Tab + 搜索 + 表格）
2. 配置编辑弹窗（动态表单 + 校验）
3. 变更历史 Timeline
4. 发布状态指示器

### Phase 5：高级功能（后期）
1. 配置灰度发布
2. 配置快照导入/导出
3. 环境差异对比（dev vs prod）
4. 配置变更审批工作流

## 8. 重构点

现有代码需要以下改造：

| 项目 | 当前方式 | 改造为 |
|------|----------|--------|
| RAG-BACKEND | `@Value("${chunk.size}")` | `configService.getInt("chunk.default_size", 500)` |
| RAG-PYTHON | `cfg = get_config()["chunk"]["default_size"]` | `config_center.get("chunk.default_size", 500)` |
| RAG-CLEANING | `cfg = get_config()["preprocessing"]["pdf"]` | `config_center.get("pdf.ocr_enabled", True)` |
| RAG-MEMORY | `cfg["engine"]["dedup_threshold"]` | `config_center.get("engine.dedup_threshold", 0.85)` |
| RAG-QUE | `cfg["engine"]["hyde_enabled"]` | `config_center.get("que.hyde_enabled", True)` |
