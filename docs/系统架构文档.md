## 4. 权限控制体系

### 4.1 系统角色 (5种)

| 角色 | 权限数 | 可见范围 |
|------|--------|----------|
| SUPER_ADMIN | 18 | 全部资源 (跨团队) |
| ADMIN | 16 | 全部资源 (跨团队) |
| REVIEWER | 6 | 所属团队 + 审核 |
| EDITOR | 7 | 所属团队 + 上传编辑 |
| VIEWER | 4 | 所属团队 (只读) |

### 4.2 团队角色 (5种)

| 角色 | 上传 | 审核 | 删除 |
|------|:---:|:---:|:---:|
| team_owner | ✅ | ✅ | ✅ |
| team_admin | ✅ | ✅ | ✅ |
| team_editor | ✅ | ❌ | ❌ |
| team_reviewer | ✅ | ✅ | ❌ |
| team_viewer | ❌ | ❌ | ❌ |

### 4.3 隔离机制

- **垂直越权**: `@PreAuthorize("hasAuthority('XXX')")` 方法级拦截
- **水平越权**: `@TeamPermission` AOP 资源归属校验
- **前端**: `v-permission` 指令 + `hasPermission()` 条件渲染

## 5. 数据流

### 文档入库
```
Upload → MinIO → Kafka(FILE_PROCESS) → CLEANING(解析+OCR+清洗)
  → cleaned.md → Kafka(CHUNK_PROCESS) → PYTHON(分块) → DB
  → 人工审核 → Kafka(EMBED_PROCESS) → PYTHON(嵌入) → Milvus+BM25
```

### 知识问答
```
Question → Java → gRPC QE(:50055) → 意图识别+查询优化
  → gRPC Retrieval(:50051) → 混合检索(向量+BM25)
  → gRPC Generation(:50052) → LLM流式回答
  → SSE/WebSocket → 前端流式展示
  → Kafka(memory.distill) → MEMORY(记忆蒸馏)
```

## 7. 关键设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 服务发现 | Nacos HTTP API | 无需 Spring Cloud 依赖, 零侵入 |
| Python 注册 | requests + 心跳线程 | 10 行代码实现 |
| Java 注册 | NacosRegistration Bean | 启动注册 + 5s 心跳 + 优雅下线 |
| 配置存储 | MySQL system_configs 表 | 复用现有基础设施 |
| 团队隔离 | team_members JOIN 过滤 | SQL 层面性能最优 |
| 权限模型 | RBAC (角色→权限→API) | 灵活可配, 无需改代码 |
