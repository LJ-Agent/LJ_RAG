## 2. 微服务拆分方案

### 2.1 目标架构

```
                          ┌─────────────┐
                          │  API Gateway │  (Spring Cloud Gateway / Nginx)
                          │  Port: 8080  │
                          └──┬──┬──┬──┬─┘
                             │  │  │  │
        ┌────────────────────┼──┼──┼──┼────────────┐
        ▼                    ▼  ▼  ▼  ▼            │
  ┌───────────┐   ┌──────────┐ ┌──────────┐  ┌─────▼────────┐
  │auth-service│   │kb-service │ │doc-service│  │qa-service    │
  │Port: 8081  │   │Port: 8082 │ │Port: 8083 │  │Port: 8084   │
  │User/Login  │   │KB CRUD    │ │Upload     │  │QA/Review     │
  │Role/Perm   │   │Team Mgmt  │ │Document   │  │ChatSession   │
  └────────────┘   └──────────┘ │ChunkReview│  │Feedback      │
                                └──────────┘  └──────────────┘
  ┌───────────┐
  │config-svc │   ← 可独立部署，也可合并到auth-service
  │Port: 8085 │
  │Sys+User   │
  │Config     │
  └───────────┘
```

### 2.2 服务职责与数据归属

| 微服务 | 端口 | 数据库 | 负责Entity | API |
|--------|------|--------|------------|-----|
| **auth-service** | 8081 | auth_db | User, Role, Permission, UserRole | /api/auth/*, /api/users/*, /api/roles/*, /api/permissions/* |
| **kb-service** | 8082 | kb_db | KnowledgeBase, Team, TeamMember, TeamKB | /api/knowledge-bases/*, /api/teams/* |
| **doc-service** | 8083 | doc_db | Document, DocumentChunk, ReviewRecord | /api/files/*, /api/chunks/*, /api/review/* |
| **qa-service** | 8084 | qa_db | ChatSession, ChatRecord, Feedback | /api/qa/*, /api/feedback/* |
| **config-service** | 8085 | config_db | SystemConfig, UserConfig | /api/configs/*, /api/user/configs/* |

### 2.3 服务间通信

```
auth-service ──gRPC──► 提供用户信息查询 (GetUser, ValidateToken)
kb-service   ──REST──► doc-service: 验证KB存在性
doc-service  ──REST──► kb-service: 查询KB归属团队
qa-service   ──gRPC──► RAG-QUE → RAG-PYTHON (检索+生成)
qa-service   ──REST──► kb-service: 查询KB列表
config-svc   ──Kafka──► 配置变更通知所有服务
```

## 3. 实施策略

### Phase 1: 抽离 config-service (最独立) — 0.5天
- 将 SystemConfigController + UserConfigController 独立为 config-service
- 共享 MySQL 过渡，后续独立数据库
- 前端代理 config API 到新端口

### Phase 2: 抽离 auth-service — 1天
- 将 AuthController + UserController + RoleController 独立
- JWT 签发/验证集中到 auth-service
- 其他服务通过 gRPC 调用 auth-service 验证 Token

### Phase 3: 拆分 kb + doc + qa — 2天
- kb-service: KB + Team 管理
- doc-service: File + Review + Chunk
- qa-service: QA Chat + Feedback

### Phase 4: 添加 API Gateway — 0.5天
- Spring Cloud Gateway 路由分发
- 统一鉴权入口

### Phase 5: 全链路测试 — 1天

**总计: 5天**

---

## 4. 风险与降级

1. **分布式事务**: 先共享 MySQL，逐步迁移独立数据库
2. **服务发现**: 初期硬编码端口，后期引入 Nacos/Consul
3. **Token 传递**: auth-service 签发 JWT，其他服务验证签名（无状态，不依赖 auth-service）
4. **降级方案**: API Gateway 支持 fallback，某个服务不可用时返回缓存或默认响应

---

## 5. 当前状态：建议渐进式改造

考虑到系统已经稳定运行，建议**渐进式拆分**而非一次性重构：

1. **第一步(已完成)**: Python 服务已微服务化 ✅
2. **第二步(当前)**: 先抽离 config-service 和 auth-service
3. **第三步(后续)**: 逐步拆分其他模块
4. **第四步(后续)**: 引入 API Gateway

**当前优先实施**: config-service 拆分（最独立、风险最低、收益明显）
